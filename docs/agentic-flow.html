Evidence-led support resolution

A support request is validated at the API boundary, classified by Laya, and routed by LangGraph to focused agents. Agents gather policy evidence from RAG and operational facts through scoped MCP tools. Deterministic rules constrain recommendations; people approve consequential proposals.

1. System architecture

Solid blue arrows show the client/API boundary. The highlighted LangGraph block owns workflow state and execution. Laya returns typed intent and route decisions; specialist agents retrieve evidence and call only scoped MCP tools.

2. Request flow

1 · Validate

FastAPI checks the ticket, identity, size, and access to the referenced synthetic record.

2 · Classify and route

Laya returns typed intent, entities, confidence, and a bounded route. LangGraph owns state and selects eligible nodes.

3 · Gather evidence

Policy agents use hybrid RAG; operational agents call allowlisted MCP tools for synthetic order and return facts.

4 · Resolve safely

Python rules constrain options. The LLM drafts from evidence. Consequential proposals pause for a reviewer.

Demo uses synthetic India order scenarios and reviewed Amazon.in policy snapshots. No live Amazon integration or refund execution. Olist is separate historical data and is not evaluated under Amazon policy.
